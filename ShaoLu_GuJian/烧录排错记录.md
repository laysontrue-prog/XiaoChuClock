# 白屏 / 卡死 排错记录（最终版）

> 现象：烧录后 **TFT 全白、按键无反应、串口无任何输出、搜不到 WiFi 热点**
>
> 排查中一共发现 **3 个独立问题**，全部定位并修复。真正的"最后一根稻草"是 **TFT_MISO 未定义**。

---

## 硬件事实（先确认清楚）

```
esptool → This chip is ESP32-C3, not ESP32
          Detected flash size: 4MB
```

**你的时钟是 ESP32-C3，不是经典 ESP32。**
工程里的 TFT 引脚也印证了这点：`MOSI=3 SCLK=2 CS=7 DC=4 RST=5`，按键 `GPIO8`。

所以 Arduino IDE 必须选 **ESP32C3 Dev Module**。

---

## 问题一：分区表读不出来（启动死循环）

串口反复刷：

```
flash_parts: partition 0 invalid magic number 0xcccc
boot: Failed to verify partition table
```

读出 Flash 发现**分区表本身是合法的**（0x8000 处 magic=0x50AA，5 个分区都对），
但引导程序报 0xcccc。原因是**镜像头里的 Flash 配置和物理芯片不匹配**（芯片 4MB，镜像头写的是 8MB 档位）。
ROM 把引导程序读进来后，引导程序会**按镜像头重新配置 Flash**，配置错了后续读取全是垃圾 → 死循环。

**修复**：整片擦除后用正确参数重烧。

| 工具选项 | 正确值 |
|---|---|
| 开发板 | **ESP32C3 Dev Module** |
| Flash Size | **4MB (32Mb)** |
| Flash Mode | **DIO** |
| 分区方案 | **Huge APP (3MB No OTA/1MB SPIFFS)** |

---

## 问题二：TFT_eSPI 2.5.43 与 core 3.3.6 不兼容

分区修好后应用能启动，但一碰 SPI 就崩：

```
Guru Meditation Error: Core 0 panic'ed (Store access fault)
MEPC : 0x4200d3ba   →  TFT_eSPI::begin_tft_write()   TFT_eSPI.cpp:81
A5   : 0x00000010   ← _spi_user 指针是 0x10
```

**根因**（宏展开对不上）：

```c
// core 3.3.6 的 soc.h：
#define REG_SPI_BASE(i)   (((i)==2) ? (DR_REG_SPI2_BASE) : (0))   // 只认外设编号 2
// 但 TFT_eSPI 2.5.43 传的是 SPI2_HOST（枚举值 = 1）：
#define SPI_PORT SPI2_HOST        // = 1
// 展开结果：
SPI_USER_REG(1) = REG_SPI_BASE(1) + 0x10 = 0 + 0x10 = 0x10   ← 崩溃地址
```

**修复**：把库换成官方 **2.5.44**（master）——它已内置 `#if ESP_ARDUINO_VERSION_MAJOR < 3 → SPI2_HOST，否则 2`。

---

## 问题三（真正的白屏元凶）：TFT_MISO 未定义

升级库之后仍然白屏、串口停在 `tft.init()`。用**里程碑打印逐层缩小**，最终定位到：

```
[P3] 即将 writecommand(0x00) 第一条SPI传输   CMD=0x00000000
[wc1] 进入 c=0x00
[wc2] begin_tft_write 完成                  USER=0x08000000
[wc3] DC_C 完成
!!! 卡在 USR   CMD=0x01000000               ← SPI_USR 写进去后永不清零！
```

### 根因

`TFT_eSPI_ESP32_C3.h` 里有这么一段：

```c
    #ifndef TFT_MISO
      #define TFT_MISO -1
    #endif
    ...
    #if defined(CONFIG_IDF_TARGET_ESP32C3)
      #if (TFT_MISO == -1)
        #undef  TFT_MISO
        #define TFT_MISO TFT_MOSI     // ← 把 MISO 别名成 MOSI（同一个脚！）
      #endif
    #endif
```

而你的 `User_Setup.h` 里 **`TFT_MISO` 是注释掉的**（默认 -1），
于是变成 `spi.begin(TFT_SCLK=2, TFT_MISO=3, TFT_MOSI=3, -1)` —— **同一个 GPIO 既当 MOSI 又当 MISO**，
ESP32-C3 的 GPSPI 初始化直接失败（关键证据：`SPI_DMA_CONF(0x30)` 停在 `0x00000000`，
正常初始化后应是 `0x00180000`）。外设没起来，第一次 SPI 传输就永远等不到 `SPI_USR` 清零 → 死等 → 白屏。

> 排查时踩过一个坑：一开始把 `#define TFT_MISO 10` 写在 **.ino 里**，还是卡。
> 因为**库是独立编译单元**，.ino 里的宏对库无效，库只认 `User_Setup.h`。
> 必须写进 `User_Setup.h` 才生效。

### 修复

在 `User_Setup.h` 里**显式指定 MISO 引脚**（屏幕没有 MISO 线，随便用一个空闲脚即可，
MISO 只作输入，不影响任何东西）：

```c
// 第 206 行附近
#define TFT_MISO 10
```

改完的 `User_Setup.h` 已在两处生效：
- `~/Documents/Arduino/libraries/TFT_eSPI/User_Setup.h` ← **IDE 实际用的是这个**
- 本工程 `libraries/TFT_eSPI/User_Setup.h`（保持一致）

### 验证

```
>>> 生效配置: SCLK=2 MOSI=3 MISO=10 CS=7 DC=4 RST=5 MODE=3
>>> tft.init() 返回 ✅
>>> 屏幕应变红 ✅
```

## 顺带一个"坑"：串口监视器要选对端口

这块板子会枚举**两个**串口：

| 端口 | 是什么 | 有固件日志吗 |
|---|---|---|
| `/dev/cu.wchusbserialXXXX` | CH340 转 UART0 | **有** ✅（`esp32c3` 默认 `CDCOnBoot=Disabled`，`Serial` 走这里） |
| `/dev/cu.usbmodemXXXX` | 芯片原生 USB-Serial-JTAG | 没有 ❌ |

**所以串口监视器要选 `wchusbserial` 那个**，或者把工具菜单里的
**USB CDC On Boot 改成 Enabled**（这样 `Serial` 就走原生 USB 口了）。

## 三个修复要点（换电脑/重装环境时照做）

1. **开发板选 ESP32C3 Dev Module**，Flash Size = 4MB，Flash Mode = DIO，分区方案 = Huge APP
2. **TFT_eSPI 用 2.5.44 或更新**（2.5.43 配 core 3.x 在 C3 上会 Store access fault）
3. **`User_Setup.h` 里必须有 `#define TFT_MISO 10`**（不写就会被别名成 MOSI 同脚 → 白屏死等）
